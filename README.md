# ID.3 蓝牙胎压小屏 · BLE TPMS Round Display

> 给没有原厂胎压数值显示的大众 ID.3（及 MEB 平台车型）做一个能"看得见四轮气压"的圆屏小仪表。
> ESP32-C3 + 1.28" 圆屏 + 4 个外置蓝牙胎压传感器，总成本约 ¥280。

## 一、项目由来

2023 款大众 ID.3 只有被动式胎压报警（靠轮速差判断），看不到具体气压值。原厂加装内置式 TPMS 需要拆胎、换气门嘴，价格上千；市面上外置太阳能款又要额外贴一块屏，不太好看。

我的想法很简单：**用一块便宜的 ESP32 圆屏开发板，直接接收外置蓝牙胎压传感器的数据并显示出来**。难的不是焊接或画界面，而是让开发板真正"听懂"传感器发出的数据——这类产品出厂只配一个手机应用，没有任何公开的通信说明。

经过反复试验，我最终**找到了让开发板稳定接收并解析传感器数据的方法**：开发板被动监听传感器广播的数据包，按固定的帧结构和换算关系还原出压力、温度与电量状态。整套东西跑在一块 56 元的板子上，加上四个传感器，总花费约 280 元。

这个仓库把硬件选型、可复现的固件、以及我整理出来的通信格式全部公开，希望别人不用再从零试一遍。

## 二、目标用户

**主要**
- 开大众 ID.3 / ID.4 等 MEB 平台车型、原车没有胎压数值显示，想低成本补上"看得见"
- 认同 DIY、愿意自己买件接线烧录，不想为原厂选装付几千块

**次要**
- 手上已有同类外置蓝牙胎压传感器（2.4GHz BLE、FF00 私有服务）的玩家 —— 通信格式部分可直接复用
- 想学 BLE 广播解析 + 圆屏 UI 的嵌入式新手 —— 代码约 900 行，结构清晰、无重框架

**不适合**
- 想用它替代原厂安全件的人（见[免责声明](#十免责声明)）
- 期待开箱即用成品的用户（需要自己接线、烧录、绑定轮位）

## 四、硬件

| 件 | 型号/规格 | 参考价 |
|---|---|---|
| 主控 + 屏 | ESP32-2424S012（ESP32-C3 + GC9A01 240×240 + CST816D 触摸） | ¥56 |
| 胎压传感器 ×4 | 外置蓝牙胎压传感器（2.4GHz BLE，0–100 PSI） | ¥47 × 4 |
| 供电 | Type-C 车充 或充电宝（开发板自带 JST1.25 电池口） | ¥15 |
| USB 线 | **要能传数据**的 Type-C 线（很多充电线只有电源） | — |

**引脚（ESP32-2424S012）**

| 用途 | 引脚 |
|---|---|
| LCD SCLK / MOSI / DC / CS | GPIO 6 / 7 / 2 / 10 |
| LCD RST | 板上直连复位 → 代码填 `-1` |
| LCD 背光 BL | **GPIO 3，高电平有效** |
| 触摸 SDA / SCL / RST | GPIO 4 / 5 / 1（I2C 地址 `0x15`） |

> ⚠️ 两个踩过的坑：
> 1. LovyanGFX 的 `Light_PWM` 通道号必须 **0~5**（ESP32-C3 的 LEDC 只有 6 个通道）。写 7 会**静默失败**、背光不亮。
> 2. GC9A01 需要 `invert = true`；触摸芯片若一直不响应，多半是没写 `0xFE=0x01` 关掉它的自动休眠。

## 五、快速开始（照着做就行，不需要任何嵌入式基础）

### 准备

- 一块 `ESP32-2424S012` 圆屏开发板、一根能传数据的 USB-C 线
- 一台 Windows 电脑（Mac / Linux 操作位置略有不同，步骤基本一致）
- 至少一个胎压传感器（建议先买 1 个验证，跑通再补齐 4 个）

### 第 0 步：装 Arduino IDE

打开 <https://www.arduino.cc/en/software> → 下载 **Windows Win 10 and newer, 64 bits** → 一路下一步装完。

### 第 1 步：让 IDE 认识这块板子

1. 打开 Arduino IDE → 左侧栏点 **开发板管理器（Boards Manager）**
2. 搜索框输入 `esp32`
3. 找到 **esp32 by Espressif Systems** → 点 **INSTALL**
4. 这一步会下载约 300MB，**进度条走完之前不要关窗口**（网络慢时可能十几分钟）

### 第 2 步：装屏幕驱动库

1. 左侧栏点 **库管理器（Library Manager）**
2. 搜索 `LovyanGFX`
3. 点 **INSTALL**（只有一个，装最新版即可）

### 第 3 步：打开本项目的固件

**文件 → 打开…** → 选择本仓库里的 `id3-tpms-ui/id3-tpms-ui.ino`

> 注意：要选 `.ino` 文件本身，不要只把文件复制出来单独打开——Arduino 要求文件夹名和文件名一致。

### 第 4 步：做三个设置（这一步最容易出错）

插上板子，然后：

| 菜单 | 选什么 | 为什么 |
|---|---|---|
| **工具 → 开发板** | `ESP32C3 Dev Module` | 板子是 ESP32-C3 |
| **工具 → USB CDC On Boot** | **Enabled** | 不设的话串口监视器一片空白 |
| **工具 → 端口** | 形如 `COM5` 的那个 | 拔插一次看哪个新出现 |

> 端口的经验：设备名带 **USB 串行设备** / **USB JTAG** 的才是这块板子；
> 蓝牙虚拟串口（BthModem）不要选。

### 第 5 步：点上传

点左上角的 **→** 图标。看到下面这行就成功了：

```
Hash of data verified.
Hard resetting via RTS pin...
```

### 第 6 步：第一次使用

1. **把传感器拧到轮胎气门嘴上**
2. 如果屏幕一直显示 `SCAN`：把传感器**松半圈**（会听到轻微漏气声）**再拧回去** —— 这个压力变化就是它的唤醒信号
3. 几秒后屏幕出现传感器 ID 和气压 → **成功**
4. 想绑定轮位：**点屏幕上对应的轮位区域** → 出现候选列表 → 点要绑的 ID（列表里没有就点 `manual` 用键盘手输 6 位 ID）→ 自动回到主页
5. 绑定会存进板子，断电重启不丢

### 出问题先看这张表

| 现象 | 原因与处理 |
|---|---|
| 端口列表里没有设备 | 换一根**能传数据**的 USB 线；或换一个 USB 口 |
| 上传报 `Failed to connect` / 超时 | 按住板子 **BOOT** 键（右上那个）再点上传，出现 `Connecting...` 时松开 |
| 屏幕亮了但串口无输出 | 工具 → USB CDC On Boot 没设 Enabled |
| 串口监视器没输出 | 波特率要选 **115200** |
| 屏幕一直 `SCAN` | 传感器没醒：拧紧后松半圈再拧回；或先把板子贴到传感器旁边试 |
| 触摸没反应 | 触摸芯片会自动休眠，固件里已写 `0xFE=0x01` 关闭；若仍无反应，检查 SDA/SCL 引脚 |
| 有数据但数值离谱 | 记录屏幕上的十六进制与参考读数，发 issue |

## 六、通信格式（本项目实测整理）

传感器不需要配对或连接，它会周期性把数据放在蓝牙广播包里。开发板只要被动监听，按下面的结构就能还原读数。

### 6.1 广播帧结构

```
前 7 字节 = 02 01 06 | 03 03 B0 FB      ← 标志位 + 16 位服务标识 0xFBB0
数据载荷（19 字节）= 广播包第 7 字节起
```

### 6.2 载荷字段

| 字节 | 含义 | 换算 |
|---|---|---|
| 4 | 电压基准 | `V = b[4] × 0.01 + 1.22` |
| 5 | 压力低 8 位 | `P(kPa) = b[5] × 3.144` |
| 6 | 温度 | `T(℃) = b[6] − 55` |
| 7 | 状态/报警 | — |
| 10 | 压力高位标志 | `b[10] == 1` 时 `P(kPa) = (b[5] + 256) × 3.144` |
| 16–18 | 传感器 ID（倒序） | `ID = b[18] b[17] b[16]` |

**实测对照**（同一传感器放气过程，与手机端读数逐一比对）：

| 帧 | b[5] | 换算压力 | 参考读数 | b[6] | 换算温度 | 参考读数 |
|---|---|---|---|---|---|---|
| 1 | 29 | 91.2 kPa | 0.91 bar ✅ | 80 | 25 ℃ | 25 ℃ ✅ |
| 2 | 22 | 69.2 kPa | 0.69 bar ✅ | 80 | 25 ℃ | 25 ℃ ✅ |
| 3 | 0 | 0 kPa | 0.08 bar ⚠️ | 81 | 26 ℃ | 26 ℃ ✅ |

### 6.3 ID 与设备地址的关系

```
设备地址 = <ID 三字节> : 11:11:11        // 后三字节为厂商固定值
例：ID 0631FB → 06:31:FB:11:11:11
```

## 七、我在这个项目里学到的三件事

这个项目对我来说不只是"做出来一个东西"，过程中真正学到的东西写在下面。做类似的蓝牙 DIY，这三块基本绕不开。

### 7.1 用 nRF Connect 读懂蓝牙广播

做蓝牙 DIY 最容易卡住的地方不是写代码，而是**根本不知道对面在发什么**。免费工具 **nRF Connect for Mobile**（Nordic 官方）能把广播包拆开给你看。

**我学会看的几项**

| 界面里的项 | 含义 | 怎么看 |
|---|---|---|
| `Address` | 设备唯一地址（MAC） | 区分"同一个设备"还是"两个不同设备" |
| `Address type` | Public / Random | 影响连接时用的地址类型，随机地址常见于低功耗设备 |
| `RSSI` | 信号强度（负值，越接近 0 越强） | **-40~-55 说明它就在手边**；-85 以下基本是邻居设备 |
| `RAW` | 原始广播数据（十六进制） | 真正的干货都在这里 |
| `Services` | 广播里声明了哪些服务 | 当筛选条件用，比看名字可靠 |

**RAW 里每一段的含义（AD 结构）**

广播包是一串 `长度 + 类型 + 数据` 小块拼起来的，常见类型：

| 类型 | 名字 | 我拿它做什么 |
|---|---|---|
| `0x01` | Flags | 通常固定前缀 `02 01 06`，可做帧头匹配 |
| `0x09` | 设备名 | 有的设备名字就是型号，可直接认 |
| `0x03` | 16 位服务 UUID 列表 | 例如 `03 03 B0 FB` → 声明服务 `0xFBB0`，最强筛选条件 |
| `0xFF` | 厂商自定义数据 | 很多传感器把数据塞在这 |
| `0x16` | 服务数据 | 同上，另一种常见携带方式 |

**怎么判断"哪个信号才是我的"**

我最后用的是这套组合判断，基本没再认错：

1. **看强度**：把设备贴到传感器上，RSSI 会从 -80 跳到 -50 上下，一眼就能从一堆邻居设备里挑出来
2. **看变化**：给轮胎放一点气，广播数据跟着变的就是它；手机、耳机、空调这些设备的包是固定的
3. **看结构**：目标设备的广播帧头很规律（都从 `02 01 06 03 03 B0 FB` 开始），长度稳定
4. **看地址**：同型号设备的地址往往有共同前缀/后缀（我这个型号统一以 `11:11:11` 结尾）

> 小技巧：nRF Connect 的扫描列表可以按地址搜索过滤，附近设备太多时先过滤再连。

### 7.2 小屏布局与图片"压缩"进固件

240×240 的圆屏看着小，但摆放规则和网页完全不同。

**① 圆形可视区是硬约束**

圆屏可视区是内切圆，屏幕四角其实**不显示**。所以我写的每行文字都要按它所在高度算一次可用宽度：

```
可用半宽 = √(R² − dy²)      R≈114（比外环 119 再留 5px）
最多字符数 = (2×半宽 − 边距) ÷ 6     // 内置字体 size1 每字符 6px 宽
```

外环半径也不是随便取的：实测 **r=119 是最后一圈完整可见的圆**，r=120 就被裁掉。

**② 局部刷新解决闪烁**

一开始我每 500ms 全屏重画，整个屏幕像在呼吸。改成三层刷新后稳了：

| 层 | 内容 | 刷新时机 |
|---|---|---|
| 静态层 | 外环、车模、ID.3 | 只在开机/清屏时 |
| 数值层 | 四轮数字、温度 | 只有收到新数据时 |
| 状态层 | 状态文字 + 状态灯 | 每 500ms（唯一会闪的地方） |

**③ 图片怎么塞进固件**

屏幕没有文件系统，图片必须变成数组编译进去。做法是用 **Python + Pillow** 把图片缩到目标尺寸，逐像素转成 **RGB565**（16 位色：R 5bit + G 6bit + B 5bit），输出一个 `uint16_t` 数组：

```python
# 仓库里带了现成脚本：tools/img2rgb565.py
pip install pillow
python tools/img2rgb565.py assets/car_big.png car_img --width 40
# → 生成 car_img.h：40×74 的车模，约 5.9KB
```

关键点：
- **尺寸要提前定**：240×240 整屏一张图约 115KB，缩到 40×74 只要 5.9KB
- **透明背景要先合成**：不合成会出现黑边
- **字节序要匹配**：我这个屏（SPI 直传）要大端序，脚本加 `--no-big` 可关
- 生成后在固件里 `lcd.pushImage(x, y, W, H, car_img)` 就能显示

### 7.3 把一串字节变成"看得懂的数"

拿到十六进制还远远没结束，还要做三件事：

1. **找帧头**：确认从第几字节开始才是有效载荷（我的情况是跳过前 7 字节）
2. **定字段偏移与单位**：哪个字节是压力低位、哪一位是压力高位、温度为什么要减 55
3. **用参考值反推系数**：这是最关键的一步 —— 没有文档，靠**同时记录两组数据**：
   - 屏幕上算出来的数值
   - 手机端显示的官方读数

   然后调整系数让两者对齐。比如压力我最后定的是 `b[5] × 3.144 = kPa`，
   用 0.91 bar 和 0.69 bar 两次放气过程核对，误差在 0.01 bar 内。

这套"抓原始值 → 找结构 → 用已知量校准"的流程，换成任何传感器都适用。
