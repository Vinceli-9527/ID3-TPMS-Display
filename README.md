# ID.3 蓝牙胎压小屏 · BLE TPMS Round Display

> 给没有原厂胎压监测的大众 ID.3（及 MEB 平台车型）做一个能"看得见四轮气压"的圆屏小仪表。
> ESP32-C3 + 1.28" 圆屏 + 4 个外置蓝牙胎压传感器，总成本约 ¥280。

## 一、项目由来

2023 款大众 ID.3 只有**被动式胎压报警**（靠轮速差判断），看不到具体气压值。原厂加装内置式 TPMS 需要拆胎、换气门嘴，价格上千；市面上外置太阳能款又丑又要额外贴一块屏。

转折点是看到小红书博主 **@调理农务** 的 DIY 方案：用 ESP32 + 外置蓝牙胎压传感器 + 一块 1.28 寸圆屏，总花费约 300 元，做出来的效果和车机风格还挺搭。

于是决定复刻并做成可复现的开源项目。过程中最大的障碍是：**这类传感器的通信协议没有任何公开文档**，官方 App 只给结果不给协议。最终通过 REA + jadx 反编译官方 App（LYTPMS 1.0.8.821），才拿到完整的广播帧格式、字段偏移、单位系数和指令校验方式 —— 这部分内容是本项目最有价值的产出，已完整记录在[协议](#六协议逆向结果)一节；选型与踩坑过程见 `docs/复刻清单.md`。

## 二、目标用户

**主要**
- 开大众 ID.3 / ID.4 等 MEB 平台车型、原车无胎压数值显示，想低成本补上"看得见"
- 认同 DIY、愿意自己买件拧螺丝，不想为原厂选装付几千块

**次要**
- 手上已有 FF00 类 BLE 胎压传感器（LYTPMS / 各类换皮 App）的玩家 —— 协议部分可直接复用
- 想学 BLE 广播解析 + 圆屏 UI 的嵌入式新手 —— 代码约 500 行，结构清晰、无明显框架依赖

**不适合**
- 想用它替代原厂安全件的人（见[免责声明](#九免责声明)）
- 期待开箱即用成品的用户（需要自己接线、烧录、绑轮位）

## 四、硬件

| 件 | 型号/规格 | 参考价 |
|---|---|---|
| 主控 + 屏 | ESP32-2424S012（ESP32-C3 + GC9A01 240×240 + CST816D 触摸） | ¥56 |
| 胎压传感器 ×4 | 外置蓝牙胎压传感器（LYTPMS 类，0–100 PSI） | ¥47 × 4 |
| 供电 | Type-C 车充 或充电宝（开发板自带 JST1.25 电池口） | ¥15 |

**引脚（ESP32-2424S012）**

| 用途 | 引脚 |
|---|---|
| LCD SCLK / MOSI / DC / CS | GPIO 6 / 7 / 2 / 10 |
| LCD RST | 板上直连复位 → 代码填 `-1` |
| LCD 背光 BL | **GPIO 3，高电平有效** |
| 触摸 SDA / SCL | GPIO 4 / 5（本版未使用） |

> ⚠️ 两个已验证的坑：
> 1. LovyanGFX 的 `Light_PWM` 通道号必须 **0~5**（ESP32-C3 的 LEDC 只有 6 个通道）。写 7 会**静默失败**、背光不亮。
> 2. GC9A01 需要 `invert = true`。

## 五、快速开始

1. Arduino IDE 安装 **esp32 by Espressif**（2.0.x 已验证）+ 库 **LovyanGFX**
2. 打开 `id3-tpms-ui/id3-tpms-ui.ino`
3. 开发板选 `ESP32C3 Dev Module`，**USB CDC On Boot = Enabled**（否则串口无输出）
4. 端口选对（板子是原生 USB，设备名类似 "USB 串行设备"）
5. 烧录 → 串口 115200 应看到 `=== ID.3 TPMS v0.1.0 ===`
6. 把传感器拧到气门嘴上（**松半圈再拧回**制造压力变化来唤醒），屏幕几秒内出现 ID 与气压

命令行烧录：

```bash
arduino-cli upload -p COM5 --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc" \
  --input-dir releases/v0.1.0 id3-tpms-ui-v0.1.0
```

## 六、协议（逆向结果）

> 以下内容通过反编译官方 App 得到，用于**互操作性**目的。
> 证据位置：`com.wicarlink.zl.BaseTireBleService2.handScanDevice`、`com.wicarlink.zl.data.bean.TireBean.parse`、
> `com.wicarlink.zl.util.BleUtil.parseState`。

### 6.1 广播帧

```
adv 前 7 字节 = 02 01 06 | 03 03 B0 FB      ← 标志位 + 16 位服务 UUID 0xFBB0
载荷（19 字节）= adv[7 .. 7+19)
```

### 6.2 载荷字段

| 字节 | 含义 | 公式 |
|---|---|---|
| 4 | 电压基准 | `V = b[4] × 0.01 + 1.22` |
| 5 | 压力低 8 位 | `P(kPa) = b[5] × 3.144` |
| 6 | 温度 | `T(℃) = b[6] − 55` |
| 7 | 状态/报警 | — |
| 10 | 压力高位标志 | `b[10] == 1` 时 `P(kPa) = (b[5] + 256) × 3.144` |
| 16–18 | 传感器 ID（倒序） | `ID = b[18] b[17] b[16]` |

**实测对照**（同一传感器放气过程）：

| 帧 | b[5] | 计算压力 | App/屏幕读数 | b[6] | 计算温度 | 屏幕 |
|---|---|---|---|---|---|---|
| 1 | 29 | 91.2 kPa | 0.91 bar ✅ | 80 | 25 ℃ | 25C ✅ |
| 2 | 22 | 69.2 kPa | 0.69 bar ✅ | 80 | 25 ℃ | 25C ✅ |
| 3 | 0 | 0 kPa | 0.08 bar ⚠️ | 81 | 26 ℃ | 26C ✅ |

### 6.3 ID 与 MAC 的关系

```
MAC = <ID 三字节> : 11:11:11        // 后三字节为厂商固定值
例：ID 0631FB → MAC 06:31:FB:11:11:11
```

### 6.4 连接式指令（本版未使用，供扩展参考）

若传感器支持连接式读写，服务 `FF00` / 数据 `FF01` / 命令 `FF02`：

```
查询: 5A A5 06 06 <id> <CS>      CS = 5A^A5^06^06^id
配对: 5A A5 06 03 <id> <CS>      CS = 5A^A5^06^03^id
```

另有 `genBleKeyMTK` / `genBleKeyUTPMS` 两种握手密钥流程（未在广播路径中验证）。
